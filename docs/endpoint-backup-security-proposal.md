# Screen Monitor 엔드포인트 백업·보안 기능 제안서

## 1. 문서 목적

Screen Monitor 데스크톱 앱에 회사 자료 보호를 위한 전체 파일 백업, 파일 변경 감시, USB·네트워크 반출 통제 기능을 추가하는 방안을 팀에서 검토하기 위한 문서다.

이 문서는 구현 확정안이 아니다. 백업 범위, 개인정보 처리, 저장 비용, 관리자 권한 및 차단 수준을 합의한 후 상세 설계와 개발을 시작한다.

## 2. 목표

- 회사 소유 Windows PC에 분산된 중요 자료를 중앙에서 안전하게 백업한다.
- 특정 폴더에만 의존하지 않고 모든 고정 드라이브의 업무 자료를 검색한다.
- 시스템 파일과 브라우저 인증정보 등 불필요하고 위험한 데이터는 수집하지 않는다.
- 최초 전체 백업 이후에는 변경된 파일만 증분 백업한다.
- USB, 외부 네트워크 및 클라우드 등을 통한 자료 반출을 조용히 탐지하고 백엔드에 기록한다.
- 직원이 UI를 닫더라도 승인된 정책에 따라 백업과 보안 감시가 계속 동작하게 한다.

### 사용자 알림 정책: Silent Audit

- 정상 백업과 보안 이벤트 수집 과정에서 직원에게 확인, 경고 또는 승인 팝업을 표시하지 않는다.
- 파일 백업, USB 연결·복사, 네트워크 반출 의심 이벤트는 백그라운드에서 자동 기록한다.
- 사용자 작업은 현재 단계에서 차단하지 않는다.
- 오류가 발생해도 직원의 조치가 꼭 필요한 경우가 아니면 로컬 팝업을 띄우지 않고 백엔드에 상태를 기록한다.
- 위험도 높은 이벤트 알림이 필요하면 직원 화면이 아니라 관리자 대시보드 또는 관리자 채널로 전달한다.

## 3. 권장 프로그램 구조

단순히 Tauri 창을 숨겨 시스템 트레이에서 실행하는 것만으로는 보안 에이전트로 충분하지 않다. 사용자가 프로세스를 종료하거나 로그아웃하면 감시가 중단될 수 있기 때문이다.

권장 구조는 다음과 같이 두 프로그램으로 나누는 것이다.

### Tauri 데스크톱 앱

- 직원 로그인
- 프로젝트와 근무 세션 관리
- 백업 진행률 및 최근 동기화 시간 표시
- 보안 정책과 오류 상태 안내
- 시스템 트레이 UI
- Windows 시작 시 자동 실행

창을 닫으면 앱을 종료하지 않고 트레이로 숨긴다. 사용자가 명시적으로 종료하려 할 때는 회사 정책에 따라 종료를 제한하거나 관리자 권한을 요구한다.

### Rust Windows 서비스

- Windows 부팅 시 사용자 로그인 전에도 자동 시작
- 파일 탐색 및 증분 백업
- 파일 시스템 변경 감시
- 암호화, 해시 계산, 업로드 재시도
- USB 장치 및 파일 복사 이벤트 감시
- 정책과 제외 경로 적용
- Tauri 앱이 종료돼도 독립적으로 동작

Tauri UI와 Windows 서비스는 로컬 IPC를 통해 상태와 명령을 주고받는다. 백업과 보안에 필요한 서버 인증정보는 일반 UI 프로세스나 브라우저 저장소에 평문으로 두지 않는다.

## 4. 전체 백업 범위

모든 고정 드라이브를 탐색하되, 모든 바이트를 무조건 서버로 복제하지 않는다. 제외 정책을 먼저 적용하고 업무 파일로 판단되는 파일만 백업한다.

기본 포함 대상:

- 사용자 문서, 바탕 화면 및 다운로드 폴더
- 프로젝트 소스와 업무 문서
- 로컬에 저장된 회사 자료
- 사용자가 추가한 데이터 드라이브의 일반 파일
- 회사가 별도로 지정한 중요 경로

기본 제외 대상:

```text
C:\Windows
C:\Program Files
C:\Program Files (x86)
C:\ProgramData
C:\$Recycle.Bin
C:\System Volume Information

*\AppData\Local\Temp
*\AppData\Local\Microsoft\Edge\User Data
*\AppData\Local\Google\Chrome\User Data
*\AppData\Roaming\Mozilla\Firefox\Profiles

pagefile.sys
hiberfil.sys
swapfile.sys
*.tmp
*.cache
```

브라우저 다운로드 폴더는 백업 대상에 포함할 수 있지만 쿠키, 세션, 저장된 비밀번호, 인증 토큰, 방문 기록 및 캐시는 제외해야 한다. 브라우저 프로필 전체 제외 여부는 실제 폴더 구조를 기준으로 세분화한다.

추가 검토가 필요한 제외 대상:

- 직원의 개인 사용이 허용된 명시적 개인 폴더
- 인증서와 개인 키
- 메신저 계정 및 대화 데이터
- 이메일 로컬 저장소
- 데이터베이스 파일
- 가상 머신 이미지
- 대용량 미디어 및 빌드 산출물
- 암호화되거나 비밀번호가 설정된 압축 파일

## 5. 백업 처리 방식

### 최초 전체 백업

1. 고정 드라이브와 대상 경로를 탐색한다.
2. 제외 규칙, 최대 파일 크기 및 파일 형식 정책을 적용한다.
3. 파일 메타데이터와 SHA-256 해시를 계산한다.
4. 파일을 일정 크기의 청크로 분할한다.
5. PC에서 파일 또는 청크를 암호화한다.
6. 암호화된 데이터를 오브젝트 스토리지에 업로드한다.
7. 경로, 파일 버전, 해시, 저장 위치 등 메타데이터를 백엔드에 기록한다.

### 증분 백업

- 파일 생성·수정·이동·삭제 이벤트를 감시한다.
- 변경된 파일이나 청크만 업로드한다.
- 동일 해시의 데이터는 중복 업로드하지 않는다.
- 파일이 계속 변경 중이면 일정 시간 안정화된 후 백업한다.
- 네트워크 연결이 없으면 로컬 대기열에 저장하고 재시도한다.
- 잠긴 파일은 재시도하며, 반드시 필요한 경우 Windows VSS 사용을 별도로 검토한다.

### 복구 및 버전 관리

- 직원, 장치, 경로 및 날짜를 기준으로 검색한다.
- 이전 버전 및 삭제된 파일을 정해진 기간 동안 복구할 수 있게 한다.
- 복구 권한을 가진 관리자만 원본을 내려받을 수 있게 한다.
- 조회, 미리보기, 다운로드 및 복원 행위를 감사 로그에 남긴다.

## 6. 저장소 구조

Railway는 API와 메타데이터 처리를 담당하고, 대용량 원본 파일 저장은 별도 S3 호환 오브젝트 스토리지를 사용하는 것을 권장한다.

- Railway API: 인증, 정책, 파일 메타데이터, 작업 상태, 감사 로그
- PostgreSQL: 파일 인덱스, 장치, 버전 및 권한 정보
- S3/R2 계열 저장소: 암호화된 파일 청크와 백업 원본
- Tauri/Rust 에이전트: 로컬 탐색, 암호화, 업로드 및 상태 보고

Railway 애플리케이션 볼륨에 전체 PC 백업을 직접 저장하면 용량 확장, 비용, 내구성, 복구 및 접근 통제가 어려워질 수 있다.

## 7. 암호화 및 권한

- 전송 구간은 TLS를 사용한다.
- 파일은 업로드 전에 클라이언트에서 암호화한다.
- 회사 또는 테넌트별로 암호화 키를 분리한다.
- 키는 소스 코드, `.env` 또는 브라우저 `localStorage`에 저장하지 않는다.
- 운영자라고 해서 모든 원본 파일을 자동으로 열람할 수 없게 역할을 분리한다.
- 복구 권한 부여와 원본 다운로드에는 강한 인증을 적용한다.
- 관리자 권한 변경과 파일 열람은 변경 불가능한 감사 기록으로 남긴다.
- 백업 데이터의 보존기간과 자동 삭제 정책을 설정한다.
- 랜섬웨어와 관리자 계정 탈취에 대비해 삭제 방지 또는 변경 불가능한 저장 정책을 검토한다.

## 8. USB 및 외부 반출 통제

USB 활동은 사용자에게 경고를 띄우거나 확인을 요구하지 않고 Silent Audit 방식으로 기록한다.

수집할 수 있는 USB 이벤트:

- 장치 연결 및 해제 시간
- 제조사, 모델, 일련번호
- 사용자와 PC 식별자
- 복사한 파일의 경로, 크기 및 해시
- 이벤트 분류와 위험도

기록 정책 예시:

- 승인 여부와 관계없이 연결된 USB 정보를 기록
- BitLocker 암호화 여부 기록
- 복사된 일반 파일의 메타데이터와 해시 기록
- 기밀 파일 복사 의심 이벤트에 높은 위험도 부여
- 대량 복사나 압축 파일 복사는 백엔드에 보안 이벤트로 기록하고 관리자에게만 알림

현재 범위는 감사와 기록이며 강제 차단은 포함하지 않는다. 향후 차단이 필요해지면 Microsoft Defender/Intune/Endpoint DLP 연동이나 파일 시스템 미니필터 드라이버를 별도 검토한다.

## 9. 네트워크 반출 통제

다음 경로를 각각 구분해 정책을 설계한다.

- 개인 이메일 첨부
- 브라우저 파일 업로드
- 승인되지 않은 클라우드 드라이브
- 메신저 파일 전송
- 외부 네트워크 공유
- FTP/SFTP
- 원격 데스크톱의 드라이브 공유
- Bluetooth 전송
- 프린터 및 PDF 출력

파일 변경 감시만으로 모든 네트워크 반출을 탐지하거나 차단할 수는 없다. 브라우저, 프로세스, 네트워크 계층을 함께 다루거나 검증된 Endpoint DLP 제품과 연동해야 한다.

## 10. 성능과 안정성 고려사항

- 최초 스캔은 CPU, 디스크 및 네트워크 사용률 제한을 적용한다.
- 업무 시간에는 낮은 우선순위로 실행하고 필요하면 유휴 시간에 속도를 높인다.
- 배터리 사용 중이거나 종량제 네트워크에서는 업로드를 일시 중지할 수 있게 한다.
- 파일 크기와 일일 업로드 한도를 정책으로 관리한다.
- 심볼릭 링크와 재분석 지점으로 인한 순환 탐색을 방지한다.
- 업로드 성공 전까지 파일 버전과 작업 상태를 안전하게 보관한다.
- 서비스 장애가 PC 부팅이나 정상적인 파일 사용을 막지 않게 한다.
- 백업 데이터가 불완전해도 성공으로 표시하지 않도록 무결성을 검증한다.

## 11. 개인정보·노무·운영 검토

전체 드라이브 백업은 업무 자료뿐 아니라 직원 또는 제3자의 개인정보가 포함될 가능성이 높다. 개발 전에 최소한 다음 사항을 문서화하고 법무·노무 담당자와 검토해야 한다.

- 회사 소유 장비와 개인 장비 중 적용 대상
- 수집 목적과 법적 근거
- 포함·제외되는 정보의 구체적인 범위
- 직원 고지 방식
- 보존기간과 퇴사 시 처리 방식
- 관리자 열람 가능 범위와 승인 절차
- 직원의 개인 사용 허용 범위
- 오탐 또는 개인 파일 수집 시 삭제·정정 절차
- 고객사 자료와 제3자 개인정보에 대한 처리 책임
- 해외 저장소 사용 여부와 데이터 위치

보안을 이유로 하더라도 목적에 필요한 범위를 정하고, 접근 권한과 보유기간을 최소화해야 한다. 전체 원본을 다루는 기능은 기술 구현뿐 아니라 내부 규정과 운영 절차가 함께 준비되어야 한다.

## 12. 단계별 개발 제안

### 1단계: 감사형 MVP

- Rust Windows 서비스 기본 구조
- Tauri 트레이 앱과 서비스 간 IPC
- 전체 고정 드라이브 파일 인벤토리
- 제외 규칙 및 중앙 정책
- 파일 메타데이터와 해시 전송
- 파일 변경 감시
- 관리자 인벤토리 조회

### 2단계: 암호화 백업

- 오브젝트 스토리지 연동
- 클라이언트 측 암호화
- 청크 및 재개 가능한 업로드
- 증분 백업과 중복 제거
- 버전 관리와 관리자 복원
- 보존기간 및 자동 삭제

### 3단계: 반출 감사

- USB 연결과 복사 이벤트 기록
- 네트워크 공유 및 동기화 폴더 감시
- 위험 파일 및 대량 복사 알림
- 관리자 보안 이벤트 화면

### 4단계: 탐지 정책 고도화

- 감사 결과와 오탐 분석
- 승인·미승인 USB 및 장치 분류
- 기밀 파일 반출 위험도 계산
- 관리자 알림과 사건 조사 워크플로
- 차단이 새 요구사항으로 확정될 경우 Defender, Intune 또는 Endpoint DLP 연동 별도 검토

## 13. 팀에서 결정해야 할 사항

개발을 시작하기 전에 다음 질문에 합의해야 한다.

1. 대상은 회사 소유 PC로만 제한하는가?
2. 모든 사용자 파일을 백업하는가, 업무 파일 형식만 백업하는가?
3. 개인 영역을 허용한다면 어느 경로로 지정할 것인가?
4. 파일당 최대 크기와 장치당 예상 데이터 용량은 얼마인가?
5. 백업 보존기간과 삭제된 파일의 복구기간은 얼마인가?
6. 원본 파일을 열람·복구할 수 있는 역할은 누구인가?

## 14. 현재 권고 결론

- Tauri 앱은 창을 닫아도 트레이에서 계속 실행한다.
- 실제 백업 엔진은 별도의 Rust Windows 서비스로 분리한다.
- 모든 고정 드라이브를 검사하되 시스템, 프로그램, 인증정보 및 캐시 영역은 제외한다.
- 최초 전체 백업 후 증분 백업으로 전환한다.
- 파일 원본은 클라이언트에서 암호화해 오브젝트 스토리지에 보관한다.
- Railway에는 API, 메타데이터 및 감사 로그만 둔다.
- USB와 네트워크 반출은 Silent Audit으로 기록하며 직원에게 경고나 확인 창을 표시하지 않는다.
- 현재 범위에는 사용자 작업 차단을 포함하지 않고, 차단 도입은 별도 의사결정으로 다룬다.
- 구현 전에 백업 범위, 보존기간, 관리자 권한과 직원 고지를 확정한다.
