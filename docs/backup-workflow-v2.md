# 백업 워크플로 v2

## 확정 원칙

백업은 스캔, 정책 편집, 계획 확정, 업로드를 서로 분리한다. 관리자가 계획을 확정하기 전에는 파일 업로드 대기열을 만들지 않는다.

## 상태 전이

```text
Scanning -> PolicyDraft -> PlanReady -> BackingUp -> Completed
     |          |             |
  진행 표시   폴더 정책 편집   관리자 백업 시작
```

- `Scanning`: PC가 폴더 구조를 순회하며 파일 수와 용량을 집계한다.
- `PolicyDraft`: 스캔이 끝났으며 관리자가 포함·제외 폴더를 편집한다.
- `PlanReady`: 현재 정책이 스냅샷으로 적용되어 백업 대상이 고정됐다.
- `BackingUp`: 고정된 대상만 순서대로 업로드한다.
- `Completed`: 고정된 계획의 처리가 끝났다.

규칙 변경은 이미 확정된 계획을 변경하지 않는다. 변경된 규칙은 다음 스캔·계획에 적용한다.

## 2단계 스캔

1. 빠른 폴더 탐색은 파일 크기와 수정 시각을 읽지 않고 디렉터리 구조만 먼저 서버에 전송한다.
2. 관리자 폴더 트리는 첫 단계의 배치를 받는 즉시 표시되므로 `C:\Users` 같은 상위 폴더를 먼저 탐색할 수 있다.
3. 두 번째 단계에서 파일 메타데이터를 읽으며 폴더별 파일 수와 용량을 점진적으로 갱신한다.
4. 정책 확정은 두 번째 단계까지 끝나 `PolicyDraft` 상태가 된 뒤에만 허용한다.

## 로컬 체크포인트

- 완료된 전체 파일 메타데이터는 직원 PC의 앱 데이터 폴더에 암호화해 저장한다.
- 임시 파일에 먼저 기록하고 원자적으로 교체해 비정상 종료 시 손상을 줄인다.
- 앱이나 서버가 재시작되어도 로컬 결과는 유지되며, 서버의 진행 상태와 대조해 중복 백업을 막는다.
- 정상적인 다음 스캔 주기에는 오래된 체크포인트를 재사용하지 않고 파일 시스템을 다시 확인한다.
- 체크포인트에는 파일 내용이 아니라 경로, 크기, 수정 시각과 집계 정보만 저장한다.

## 관리자 사용 순서

1. 스캔 진행률과 현재 경로를 확인한다.
2. 스캔 완료 후 폴더 목록에서 포함·제외 정책을 설정한다.
3. `백업 계획 확정`을 눌러 대상 파일 수와 용량을 고정한다.
4. `확정된 백업 시작`을 눌러 업로드한다.
5. 완료, 실패, 남은 파일과 최근 처리 시각을 확인한다.

## 테스트 기준

- 스캔 중 업로드 대기열은 항상 0건이어야 한다.
- 정책 확정 전 백업 시작 요청은 거절해야 한다.
- 더 구체적인 하위 폴더 규칙이 우선해야 한다.
- 확정 후 규칙을 바꿔도 기존 계획은 변하지 않아야 한다.
- 로컬 체크포인트는 암호화 저장되고 동일한 루트에서만 재사용해야 한다.
